# bench-triage

kitsuneOS bench capture triage, built as a Mistral Studio Workflow.
Model-pinned reads for the pull → build → flash → capture bench rounds:
the Architect's local agent captures verbatim USB CDC output from the
IRIS DVI board (Feather RP2350 HSTX), and the capture gets routed through
this workflow for a fixed verdict block.

Drafted by ⚡ Piko, Kitsune Research Industries. Lives in the KRI forge
infrastructure home; deploys with `./bench-triage` as the build context.

## Modes

| mode | does | intended model |
| --- | --- | --- |
| `triage` | one capture → fixed verdict block (`STATUS / EVIDENCE / TIMING / NEXT-ROUND`) | cheap catalog model (swap via `TRIAGE_MODEL`) |
| `debug` | capture + hypothesis → ≤3 ranked hypotheses, cheapest discriminating test each | Mistral Large 4 |
| `ab` | same capture through **both** readers, verdicts side by side | both — the honest Le Chonk test |

Input schema (see `bench_triage.py`):

```json
{
  "capture": "<verbatim 115200 baud USB CDC capture>",
  "mode": "triage | debug | ab",
  "hypothesis": "optional — debug mode only",
  "triage_model": "optional per-execution override",
  "debug_model": "optional per-execution override"
}
```

Models default to `mistral-large-latest` (resolves to Mistral Large 4 at
time of writing). **Pin dated model ids** from
https://docs.mistral.ai/models via the `TRIAGE_MODEL` / `DEBUG_MODEL`
environment variables once validated, so a future `-latest` rotation
cannot silently swap the model under a running bench program.

## Scaffolding provenance

The workflow file (`src/workflows/bench_triage.py`) follows the documented
Workflows SDK shape exactly (`@workflows.workflow.define` /
`@workflows.workflow.entrypoint` / `@workflows.activity`). The worker
entrypoint, Dockerfile, and Makefile mirror the files generated by:

```bash
uvx mistralai-workflows-cli@latest setup
```

If the deploy build rejects `src/entrypoints/worker.py` (the discovery /
`run_worker` import seam is the only scaffold-generated detail), regenerate
the scaffold with the CLI and drop `src/workflows/bench_triage.py` into
`src/workflows/` unchanged.

## Deploying (managed deployment)

Prerequisites (Architect-side):

1. **Pay-as-you-go enabled** on the Kitsune Kits organization — managed
   deployments require it; Pro alone does not qualify.
2. **Mistral GitHub App installed** on this repository:
   https://github.com/apps/mistralai — and a GitHub credential connected
   in the console.

Deploy with build context `./bench-triage` (console → Workflows →
Deployments, or API). No API key ships in the image: the platform injects
a service-account token into the worker at runtime.

## Using it

Once deployed, invoke from the Vibe Work composer (**+** → Workflows),
from the console, or via the API. Typical bench flow:

1. Run the paste-ready bench prompt on the local agent (pull → HEAD check →
   build → BOOTSEL flash → verbatim capture → `capture.txt`).
2. Send the capture into this workflow with `mode: "triage"` (or `"ab"`
   for the first few rounds, until the model choice has earned trust).
3. Bench verdicts (not interim hypotheses) land in `PROJECT-STATUS.md` in
   the kitsuneOS repo.
