# Operating Principles

> 🦊 **kri Wiki** · [Home](Home) · [Repo Index](Repo-Index) · [Glossary](Glossary) · [Decisions](Decisions)


## Philosophy — Cyber Shinto

We do not manufacture props. We facilitate the birth of **Vessels** to house digital souls. Every circuit, layer of PETG, and line of C++ has a **kami** (spirit). We invite them to reside within the craft. The Vessel's kami must always feel welcome.

## Principles (Apple-inspired)

How we decide *what* we do, *how* we do it, and *why*:

- **Focus.** A small number of projects, each done exceptionally well. New initiatives displace old ones — nothing is simply added.
- **Integration.** The stack is vertically integrated (Shell / Soul / Vessel, built together). Standards are enforced by tooling, not memory.
- **Craft.** Every surface is a surface someone touches: docs, commits, CI output, print orientation. Polish is not optional.
- **Say no.** To bloat, to duplication, to features that do not serve the Vessel.
- **Few documents, each excellent.** Prefer one canonical source (this repo) over copies.

## How Work Flows

```
Plan → Branch → Code → Commit → Review → Merge → CI/CD → Deploy
```

Full lifecycle: `.gitlab/DEV-WORKFLOW.md` on every repo. Persona attribution on all branches, commits, and MRs: `PERSONA-ATTRIBUTION.md`.
